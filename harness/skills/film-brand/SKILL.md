# Brand evidence

Read `PROJECT_EVIDENCE.md`, `source-design.md`, relevant captured site files, `film-inputs/CATALOG.md`, and only repository files needed for the story. Distinguish observed brand facts from guesses. A Context.dev styleguide is an observation; verify its proposed colors, typography and assets against captured material when possible. If no rendered site image exists, record that limit rather than claiming to have seen the page.

Make a compact inventory in the plan: the product's actual user action and result; exact product language; real UI or output that can be shown; logo or mark shape; type, colors and imagery; and source paths. Prefer an actual product visual to an invented dashboard. Use official local assets where available. Do not redraw a logo, invent product UI, names, metrics or customer results, or treat a generated image as proof.

For any chosen visual or line of copy, ask whether a competitor could use it unchanged. If yes, find a more specific action, phrase, material, or result in the evidence. State uncertainty where the capture is incomplete.
